# Spring Web 심화 - TIL

## @RequestParam

### 기본 사용

쿼리 파라미터나 Form 데이터를 받을 수 있습니다.

```java
@GetMapping("/users")
public String getUser(@RequestParam String name, @RequestParam int age) {
    // name과 age 파라미터 사용
}
```

### Form 데이터 처리

Form 데이터도 받을 수 있습니다.

**제약사항**
- JSON은 받을 수 없습니다.

---

## @ModelAttribute

### 기본 사용

Form 데이터를 객체로 매핑해서 사용할 수 있습니다.

```java
@PostMapping("/users")
public String createUser(@ModelAttribute UserForm userForm) {
    // Form 데이터가 UserForm 객체로 바인딩됨
}
```

### 요구사항

**Setter 필수**
- Setter가 있어야 데이터 바인딩이 가능합니다.

**Builder 대응 가능**
- Builder 패턴으로도 객체 생성이 가능합니다.

## JSON 반환

### HttpMessageConverter 동작

JSON을 반환할 때는 ViewResolver가 아닌 **HttpMessageConverter**가 동작합니다.

### 반환 가능한 타입

```java
// Map 반환
@GetMapping("/data")
public Map<String, Object> getData() {
    Map<String, Object> data = new HashMap<>();
    data.put("name", "John");
    return data;
}

// 객체 반환
@GetMapping("/user")
public User getUser() {
    return new User("John", 25);
}
```

## ResponseEntity

### 개념

HTTP 응답을 세밀하게 제어할 수 있는 클래스입니다.

### 생성 방법

**1. new 키워드 사용**

```java
return new ResponseEntity<>(user, HttpStatus.CREATED);
```

**2. 체이닝 방식**

```java
return ResponseEntity
    .status(HttpStatus.CREATED)
    .body(user);
```

### 매개변수

**2개 매개변수**
- Body
- 상태 코드

**3개 매개변수**
- Body
- Header
- 상태 코드

### 상태 코드

Enum 클래스로 제공됩니다.

```java
HttpStatus.OK           // 200
HttpStatus.CREATED      // 201
HttpStatus.BAD_REQUEST  // 400
HttpStatus.NOT_FOUND    // 404
```

### Header 처리

**MultiValueMap**
- Map인데 MultiValue를 가지고 있습니다.
- 1개의 키에 여러 개의 value를 할당할 수 있습니다.

```java
HttpHeaders headers = new HttpHeaders();
headers.add("Custom-Header", "value1");
headers.add("Custom-Header", "value2");

return new ResponseEntity<>(user, headers, HttpStatus.OK);
```

### 식별자 ID 처리

**Location 헤더 사용**

생성된 리소스의 식별자 ID는 Header의 Location에 담습니다.

```java
HttpHeaders headers = new HttpHeaders();
headers.setLocation(URI.create("/v1/members/1")); // 1이 식별자 ID

return new ResponseEntity<>(headers, HttpStatus.CREATED);
```

## RestClient

### 개념

서버에서 직접 요청을 보낼 때 사용합니다. Spring 애플리케이션이 클라이언트의 역할을 수행하도록 합니다.

```java
@Service
public class ExternalApiService {
    
    private final RestClient restClient;
    
    public ExternalApiService(RestClient.Builder builder) {
        this.restClient = builder
            .baseUrl("https://api.example.com")
            .build();
    }
    
    public User getUser(Long id) {
        return restClient.get()
            .uri("/users/{id}", id)
            .retrieve()
            .body(User.class);
    }
}
```

## 예외 처리

### @ExceptionHandler

예외 발생 시 catch해서 사용합니다. **Controller 계층에서 사용**합니다.

```java
@Controller
public class UserController {
    
    @ExceptionHandler(UserNotFoundException.class)
    public ResponseEntity<String> handleUserNotFound(UserNotFoundException e) {
        return ResponseEntity
            .status(HttpStatus.NOT_FOUND)
            .body(e.getMessage());
    }
}
```

### @ControllerAdvice / @RestControllerAdvice

**전역 예외 처리**에 사용합니다.

**@RestControllerAdvice**
- JSON으로 변환하여 응답합니다.
- 예외를 처리하고 싶으면 이것을 사용하세요.

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(UserNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleUserNotFound(UserNotFoundException e) {
        ErrorResponse error = new ErrorResponse(
            HttpStatus.NOT_FOUND.value(),
            e.getMessage()
        );
        return ResponseEntity
            .status(HttpStatus.NOT_FOUND)
            .body(error);
    }
    
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGeneral(Exception e) {
        ErrorResponse error = new ErrorResponse(
            HttpStatus.INTERNAL_SERVER_ERROR.value(),
            "서버 오류가 발생했습니다."
        );
        return ResponseEntity
            .status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(error);
    }
}
```

## 필터와 인증/인가

### 실행 순서

```
Client 요청
   ↓
서블릿 필터 (인증/인가 - Spring Security)
   ↓
DispatcherServlet
   ↓
Controller
```

DispatcherServlet **앞**에 인증/인가 처리를 위한 서블릿 필터가 적용됩니다.

## 동기/비동기와 블로킹/논블로킹

### 차이점

**블로킹 vs 논블로킹**과 **동기 vs 비동기**는 다른 개념입니다.

### 논블로킹의 활용

비동기 처리를 위해서 논블로킹을 활용하는 것입니다.
- 논블로킹을 활용하지 않을 수도 있습니다.

### 논블로킹의 장점

**더 적은 스레드로 더 많은 일을 할 수 있습니다.**

### Spring WebFlux

논블로킹 방식의 Spring 프레임워크입니다.

```java
@RestController
public class UserController {
    
    @GetMapping("/users/{id}")
    public Mono<User> getUser(@PathVariable Long id) {
        return userService.findById(id);
    }
    
    @GetMapping("/users")
    public Flux<User> getAllUsers() {
        return userService.findAll();
    }
}
```

## 핵심 정리

- **@RequestParam**: 쿼리 파라미터, Form 데이터 (JSON 불가)
- **@ModelAttribute**: Form 데이터를 객체로 매핑 (Setter 필수)
- **JSON 반환**: HttpMessageConverter 사용 (ViewResolver 아님)
- **ResponseEntity**: 상태 코드, 헤더, Body를 세밀하게 제어
- **MultiValueMap**: 1개의 키에 여러 value 할당 가능
- **Location 헤더**: 생성된 리소스의 식별자 ID 전달
- **RestClient**: 서버가 클라이언트 역할 수행
- **@ExceptionHandler**: 컨트롤러 레벨 예외 처리
- **@RestControllerAdvice**: 전역 예외 처리 (JSON 반환)
- **서블릿 필터**: DispatcherServlet 앞에서 인증/인가 처리
- **논블로킹**: 적은 스레드로 많은 일 처리 (WebFlux)
