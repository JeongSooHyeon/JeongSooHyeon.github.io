# 덕후감 프로젝트 개발 리포트

정수현


### 1. 프로젝트 개요
덕후감은 도서 기반 리뷰 커뮤니티 플랫폼이다. 사용자가 책을 등록하고 리뷰와 댓글을 작성하며, 인기 도서와 리뷰를 대시보드에서 확인할 수 있는 서비스다. 팀 4인이 도메인별로 역할을 나눠 약 3주간 진행한 Spring Boot 기반의 백엔드 프로젝트다.


### 2. 담당한 작업
Book 도메인 전담 및 CI/CD 파이프라인 구축을 담당했다.
Book 도메인
•	Book 엔티티 설계 
•	도서 CRUD API 구현 (생성 / 조회 / 수정 / 삭제 / 영구삭제)
•	커서 기반 페이지네이션 목록 조회 (jOOQ 활용)
•	네이버 Book API 연동 (ISBN 검색)
•	OCR.space API 연동 (이미지에서 ISBN 자동 추출 → 도서 정보 반환) — PR #170
•	AWS S3 썸네일 업로드 (파일 타입 검증, TransactionSynchronizationManager로 S3-DB 정합성 처리) — PR #164
•	분산락 적용 (createBook / updateBook / deleteBook에 @DistributedLock)
인프라 & CI/CD
•	GitHub Actions CI 파이프라인 구축 (dev PR 시 테스트 + JaCoCo 80% 커버리지 검증)
•	GitHub Actions CD 파이프라인 구축 (main push 시 ECR 빌드 → ECS 자동 배포)
•	AWS ECS / EC2 인프라 구성 (Fargate → EC2 전환, IAM 역할 설정, ecs-task-def 관리)
•	ElastiCache Redis 연동 전환 (EC2 직접 설치 → Valkey ElastiCache로 변경)
•	CodeRabbit AI 코드리뷰 설정 (.coderabbit.yaml, 리뷰 규칙 작성)


### 3. 기술적 성과
커서 기반 페이지네이션 jOOQ의 DSL.row().gt/lt()로 (메인 정렬 컬럼, createdAt) 복합 커서 조건을 구현했다. publishedDate, rating, reviewCount 등 타입이 다른 정렬 컬럼을 parseCursor()에서 각각 적절한 타입으로 변환했다.
AWS S3 썸네일 업로드 파일 타입 검증과 서버 측 확장자 매핑을 적용했다. TransactionSynchronizationManager의 afterCommit()으로 DB 커밋 이후 기존 썸네일을 삭제하고, afterCompletion(STATUS_ROLLED_BACK)으로 롤백 시 새로 업로드한 파일을 보상 삭제하는 방식으로 S3-DB 정합성을 처리했다.
AWS ECS + ECR CI/CD 파이프라인 GitHub Actions로 자동 빌드/배포 파이프라인을 구축했다. dev PR 시 Testcontainers 기반 테스트와 JaCoCo 80% 커버리지 검증이 실행되고, main push 시 Docker 이미지를 ECR에 올려 ECS에 자동 배포된다.
AWS ElastiCache(Valkey) 연동 EC2에 Redis를 직접 설치하던 방식에서 관리형 ElastiCache로 전환했다. RedissonProdConfig를 @Profile("prod")로 분리해 로컬/운영 환경의 Redis 설정을 독립적으로 관리했다.
테스트 환경 인프라 격리 @Profile("test")로 S3/OCR 실제 호출을 차단하고 S3ServiceStub, OcrSpaceClientStub으로 테스트 환경을 분리했다.


### 4. 문제점 및 해결 과정
S3 테스트 환경 빈 충돌, @Import(AppProperties.class)로 컴포넌트 스캔 범위가 넓어지면서 @Profile("!test")인 S3ServiceImpl까지 로드되어 S3Client 빈을 찾지 못하는 오류가 발생했다. S3ServiceImpl에 @Profile("!test")를 명시하고 S3ServiceStub을 @Profile("test")로 별도 등록해 해결했다.
clustercfg. 형식의 클러스터 모드 엔드포인트를 Redisson이 파싱하지 못해 MalformedURLException이 발생했다. 클러스터 모드를 비활성화한 후 기본 엔드포인트로 재생성해 해결했다.
트랜잭션 롤백 시 S3-DB 데이터 불일치 도서 수정 시 새 썸네일을 업로드한 뒤 기존 썸네일을 트랜잭션 안에서 즉시 삭제하면 DB 롤백 시 S3 파일만 삭제되는 불일치가 발생할 수 있었다. TransactionSynchronizationManager.afterCommit()으로 커밋 이후에 기존 파일을 삭제하고, afterCompletion(STATUS_ROLLED_BACK)으로 새로 업로드한 파일을 보상 삭제하도록 수정해 해결했다.
gradle-wrapper.jar가 .gitignore에 포함되어 있어 CI가 계속 실패했다. Gradle을 직접 설치한 뒤 gradle-wrapper.properties의 버전을 팀 프로젝트 버전(8.14.4)에 맞게 수정해 해결했다. 초기 단계라 커버리지가 37%로 80% 기준에 미달해 continue-on-error: true를 설정해 CI가 블로킹되지 않도록 처리했다.
t3.micro에서 t3.small로 인스턴스 타입을 변경했을 때 ECS Agent가 이전 인스턴스 정보를 캐싱하고 있어 실행에 실패했다. /var/lib/ecs/data/agent.db를 삭제한 뒤 Agent를 재시작해 해결했다.


### 5. 협업 및 피드백
작업 시작과 완료 시점에 팀원들과 진행 상황을 공유하고, 이슈 카드를 꼼꼼히 작성해 전체 진행 상황을 파악하기 좋았다. 팀원이 병목에 걸렸을 때 함께 원인을 찾고 해결하는 과정에서 팀 협업의 중요성을 다시 느꼈다. CodeRabbit AI 리뷰와 팀원 크로스 리뷰를 병행해 놓치기 쉬운 문제를 조기에 잡을 수 있었다. 다음 프로젝트에서는 더 적극적으로 기여하고 싶다.


### 6. 코드 품질 및 최적화
NaverBookProperties, S3Properties, OcrProperties, RedisProperties 등 외부 설정을 @ConfigurationProperties로 타입 안전하게 관리했다. 운영 시크릿이 포함된 Properties 클래스는 toString()을 재정의해 로그 노출을 차단했다.
S3ServiceImpl/S3ServiceStub, S3LocalConfig/S3ProdConfig를 @Profile 기반으로 분리해 로컬과 운영 환경을 독립적으로 관리했다.
자동 코드리뷰 PR마다 CodeRabbit이 자동으로 리뷰해 컨벤션 위반, 예외 처리 누락, 보안 이슈 등을 조기에 발견했다.
복잡한 조회 쿼리는 JPA 대신 jOOQ로 최적화된 SQL을 직접 작성했다.


### 7. 향후 개선 사항 및 제안
현재 원본 이미지를 S3에 그대로 업로드하고 있어, 업로드 전 서버에서 리사이징 처리를 추가하면 저장 비용과 로딩 속도를 개선할 수 있다.
현재 @DistributedLock과 @Transactional을 같은 메서드에 적용하고 있어 트랜잭션 커밋 전 락이 해제되는 문제가 생길 수 있다. 락을 처리하는 외부 메서드와 트랜잭션 로직을 담는 내부 메서드로 분리하는 것을 고려해야 한다.
@Profile 기반 Stub 전략 표준화 외부 API 의존성이 많은 프로젝트일수록 @Profile("test") 기반 Stub 패턴을 팀 표준으로 정착시키면 테스트 안정성이 높아진다.
